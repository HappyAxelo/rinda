# Changes 2026-11-26: site forecast no longer stale, and live forecasts get their full inputs

## What the user saw

`https://rinda.onrender.com` showed "Forecast stale · 15 d old" and "0 of 531 locations with a potential new-water
signal". The overview set Inspect to 0.

## Causes

1. **Stale.** The 600-point v3 site forecast was refreshed by hand only (the 13 November addendum says so); the last
   refresh was the 11 November pass. The 06:00 task refreshed only the 20 m outlook.
2. **Zero signals: a live-input defect.** The model's target-pass inputs (track, gap, and the target-track memory
   `TO_*`) were read from the pass at the target date, looked up among passes already acquired
   (`habitat-forecast/src/mhf/features/history.py`, `_target_acquisition`). In evaluation that pass always existed.
   In a live issue it has not been acquired yet, so these inputs were empty. The 7-day rain forecast had the same
   flaw (`nwp_features` reads the run of the issue date from rows dated after it), and ERA5-Land soil moisture is
   published about 5 days late. With those inputs empty the stored models never reach the alert line: on the
   forward window they produced **0 alerts** (table below). The 11 November issue scores 38 alerts once its target
   pass exists, and the 14-day issues of 4 and 5 November were affected the same way.
3. **Found while fixing.** `10_extract_pc.py weather` rewrote `era5land_daily.csv` and
   `nwp_previous_runs_daily.csv` with only the requested window. A short `--start` erased the history. Restored from
   the backup taken before the run; history is complete from 2023-03-01.

## Fixes

| File | Change |
|---|---|
| `habitat-forecast/src/mhf/features/history.py` | When the target window lies beyond the site's newest pass, project the target pass from passes of the last 48 days on the 12-day repeat cycle (`TARGET_FROM_SCHEDULE` = 1). Rows with a real target pass are unchanged. `FORCE_SCHEDULE_FROM` is an evaluation hook only. |
| `habitat-forecast/scripts/10_extract_pc.py` | Weather merges into the stored series instead of overwriting; forecast-rain runs fetched to end + 8 days; leads whose run had not been issued by `--end` are blanked (the feed repeats the newest run under them). |
| `habitat-forecast/scripts/v2_study.py` | ERA5-Land soil moisture and temperature carry the last published value forward, at most 10 days. |
| `habitat-forecast/scripts/run_g20_daily.ps1` | After the 20 m outlook: extract S1, S2 and weather for the last 16 days, then `v3_issue_current.py`. The site forecast is now refreshed daily. |
| `habitat-forecast/scripts/v3_live_inputs_check.py` | New: scores the forward window with real, projected and empty target-pass inputs. Output `outputs/v3/live_inputs_check.json`. |
| `habitat-forecast/tests/test_pipeline.py` | Regression test for the projection. 15 tests pass. |
| `web/js/views/overview.js` | The folded site-forecast line states issue date, freshness and signal count instead of "research archive". Service-worker cache v6. |
