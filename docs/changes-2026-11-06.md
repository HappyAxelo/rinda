# Changes 2026-11-06: programme uptake

## Why

The 6 Nov review looked at RINDA as two users would see it: a district vector-control officer and a national malaria
programme manager. It found gaps that would block RBC or the Ministry of Health from adopting RINDA, even in a
controlled evaluation. Eight changes were agreed and built. None of them changes the forecast, the model or the
honest status line. RINDA is still **ready for controlled testing, not validated for intervention decisions**, and
nothing here measures or claims an effect on malaria.

## Gaps found and what was done

| # | Gap | Change | Status |
|---|---|---|---|
| 1 | No way to measure use for a RE-AIM/CFIR evaluation | **Monitoring & Reporting → Indicators**: 17 RE-AIM indicators counted from RINDA's own records. Reach, effectiveness (field evidence only), adoption by role, implementation fidelity, maintenance, weekly activity, plus a "not measured" list | Built |
| 2 | No reports in the form RBC uses; no HMIS route | **Weekly LSM report** (A4, English, and Kinyarwanda draft) for any ISO epidemiological week. **DHIS2 `dataValueSet` export** (JSON and DHIS2 import CSV), mapped through `config/dhis2_mapping.json` | Built; DHIS2 UIDs pending from the RBC HMIS team |
| 3 | Field form only accepted the 600 radar points; no larval density or habitat attributes | Officers can register a **new habitat** from GPS. It gets its own code (H0001…) that can be inspected, reviewed, treated and followed up. New fields: **habitat permanence**, **sun exposure**, **distance to nearest house**. **Larvae per dip** is derived and shown | Built |
| 4 | Console needed a connection to open | **Offline app shell**: a service worker caches the console, plus the officer's own tasks, habitats and account on the device. Saved API answers are deleted at sign-out. Writes still go through the idempotent offline queue | Built |
| 5 | English only | **EN/RW switch** in the top bar, saved per account. Navigation and field screens have **draft** Kinyarwanda, flagged with a banner, for terminology sessions (backlog B-11) | Built as a draft |
| 6 | Roles did not match RBC job titles; no national read-only view | Each role shows a **proposed RBC job title**. New **Programme manager** role: indicators and reports across the area, no record-level field detail, no operational actions. Accounts gain **district**, **phone** and **language** | Built; mapping to be confirmed with RBC |
| 7 | No SMS or WhatsApp alerts | **Message outbox**: assigning a task drafts a notice to the assignee in their language, and supervisors can prepare a weekly digest. No provider is connected, so nothing is sent automatically. Messages are copied, sent by hand and marked sent | Built; provider needs approval and a contract |
| 8 | No path to hosting owned by RBC, and no data-governance documents | `docs/hosting-rbc.md`, `docs/data-sharing-agreement-template.md`, `docs/dpia-template.md` | Drafts for RBC legal, ICT and data-protection review |

Not done, because it needs data RINDA does not have: names for each Cell and Village. That needs the NISR
administrative boundaries.

## Rules kept

- Indicators with no records show "no data", never 0%. Shares based on fewer than 20 records are marked "few records".
- Demonstration records are excluded from indicators and reports on an operational deployment. On a demonstration
  deployment they are included and labelled, and DHIS2 values carry the comment `DEMONSTRATION DATA - DO NOT IMPORT`.
- DHIS2 exports keep `UNMAPPED:` identifiers until the mapping is filled in, so an accidental import fails instead of
  writing to the wrong data element. RINDA never sends data to DHIS2 itself.
- Kinyarwanda text is labelled as a draft everywhere it appears: interface banner, weekly report and message channel.
- Phone numbers are visible only to administrators and are shown masked in the outbox.

## How it was checked

- `pytest -q tests`: 44 passed (30 existing, 14 new).
- In the browser, demonstration mode: a field officer registered habitat H0001 from the form (larvae per dip shown
  while typing). A supervisor assigned a follow-up to H0001, which drafted an SMS notice. A weekly digest was
  prepared. The programme manager saw indicators and the weekly report/DHIS2 tab, but not field records. The RW
  switch translated the navigation and field screens and showed the draft banner.
- Offline: headless Edge loaded RINDA online as a field officer, then went offline and reloaded. The console started
  with the offline banner and the officer's task list.

- Memory: the CI request sequence was run on Windows against the previous commit and this version, twice each.
  Peak working set was 391 / 407 MB before and 408 / 406 MB after, so there is no measurable change. These are
  Windows numbers; the CI guard measures Linux peak RSS.

## Memory fix (same day, after the first CI run)

CI's memory guard failed on this branch (Linux peak RSS 569 MB against 460 MB). It had already failed on `main`
since engine 3.0.0 (506 MB on 16 Oct; 413 MB before). Causes and fixes:

- **Unpinned dependencies.** `>=` pins let each CI run install the newest releases. pandas 3 now holds text columns
  in Arrow memory. `requirements.txt` now pins the exact versions tested here.
- **Arrow's memory pool keeps freed memory.** Reading the two v3 window parquets (73 MB of data) grew the process by
  about 130 MB. `ARROW_DEFAULT_MEMORY_POOL=system` is now set before pandas loads, in `main.py` and `engine.py`.
- **The v3 window was re-read from parquet at every start.** It is now cached as a pickle in `var/models/` (as the
  v1 path already did), with `site_id` as a category. Docker builds and CI's warm-up step create the cache.
- Repeated text columns in the forecast archive (`site_id`, risk class, uncertainty band, decision) are now
  categories.

Windows peak working set on the CI request sequence: about 407 MB before, 347–356 MB after. Linux is measured by CI.

## Known limits

- The interface translation covers navigation and field screens only. Other pages stay in English.
- The offline shell keeps the last answers the device saw. It does not prefetch forecasts or maps, and map tiles
  need a connection.
- Indicator I2 (assignment to observation) uses the device's observation time, which officers can edit.
- The national view covers the single onboarded area. Multi-district scoping arrives with the second area.
