# Changes 2026-10-16: engine 3.0.0, v3 forecast model

## What changed

RINDA used to serve the v1 study model (XGBoost, PR-AUC 0.581 at 7 days), which a 30-day water-frequency
persistence rule beat. It now serves **v3**, built in `habitat-forecast` (`scripts/v3_retrain.py`):

- v2 design (orbit-harmonised Sentinel-1 RTC labels, orbit-aware radar history, terrain, Sentinel-2;
  XGBoost + LightGBM), with no re-tuning.
- Refit on a fixed cadence: every 14 days at the 7-day horizon, every 28 days with 3 seeds at the 14-day horizon.
  The cadence was chosen on Jan–Aug 2025 only.
- Calibration, alert lines and conformal pool are re-estimated at each refit from **earlier out-of-sample
  forecasts only**.
- Operational models trained on every labelled row: to 2026-09-30 (h = 7) and 2026-09-24 (h = 14).

## Results (rolling out-of-sample, Sep 2025 – Sep 2026, identical rows)

| | 7 days | 14 days |
|---|---|---|
| v3 PR-AUC (95% CI) | 0.786 (0.733–0.828) | 0.663 (0.598–0.703) |
| frozen v2 | 0.745 | 0.642 |
| persistence (B1) | 0.570 | 0.446 |
| High-priority alerts: precision / recall | 0.75 / 0.63 | 0.72 / 0.49 |
| v2 operating line: precision / recall | 0.62 / 0.77 | 0.53 / 0.72 |

Caveats:
- Feb–Sep 2026 was blind for v2 but not for v3.
- At 14 days on Feb–Sep 2026 alone, v3 and v2 are level (0.674 vs 0.677).
- The 0.75 precision target was met at 7 days and not quite at 14 days.

## Verification categories (behaviour change)

Class-conditional 90% conformal sets met their coverage target, but sets containing only "formation" were right just
0.42 (7 d) and 0.31 (14 d) of the time. The categories are therefore now:

| Category | Rule | Share of site-days (7 d) | Observed formation rate |
|---|---|---|---|
| High priority | probability ≥ high-precision alert line | 2.8% | 0.75 |
| Insufficient evidence | below the line, 90% set does not rule formation out | 10.0% | 0.12 |
| Lower priority | 90% set rules formation out | 87.2% | 0.001 |

`config/operational_rules.json` text ("conformal_set == {formation}") describes the old rule and should be revised
with the partner before the rules version is approved.

## Files

- `study/v3/`: models, out-of-sample forecast archive (`product_h*.csv`), model inputs for explanations
  (`window_h*.parquet`), harmonised radar series, `model_card.json`.
- `study/src/mhf/v3.py`, `features/history.py`: copied from habitat-forecast so the models unpickle.
- Server: `engine.py` (v3 adapter, feature families, scenario rain columns), `data.py`, `rules.py`, `main.py`,
  `bulletin.py`. Web: `views/assurance.js` (v3 section; v1 kept as the archived study run), `views/help.js`.
- `requirements.txt`: adds `lightgbm`.

## Known limits

- Peak memory measured on Windows was 445 MB, against the 460 MB CI budget for the 512 MB Render plan.
- Explanations and scenarios use the current operational model. The archived probability is the one issued
  at the time, so the two can differ slightly (e.g. 0.869 vs 0.863).
- The "weather last day" input shown with each forecast is the Gikomero station record (ends 2026-01-15).
  v3 itself uses gridded rainfall, which adds no measurable skill.
